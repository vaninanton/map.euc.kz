# Скилл: обновление велодорожек Алматы

**OSM — единственный источник истины**, не «подсказка для сверки». Так было
не всегда: в PR #176 пробовали точечно сверять OSM со старым датасетом
Velojol и патчить только расхождения — вручную выискивать дубли и решать,
что удалить, оказалось ненадёжно (пример: `alm30` и `alm109`, обе «ул.
Сатпаева», были приняты за дубль, хотя это две разные параллельные дорожки).
Решение владельца (2026-07-30) — прекратить точечные патчи, доверять OSM
целиком и пересобирать файл заново при каждом обновлении.

Исходные данные Velojol (`velojol.kz/static/data/cities/almaty.json`,
упомянутый в `src/types/velojol.ts`) с 2026-07-29 недоступны (404, сайт жив,
эндпоинт с данными пропал) — ещё одна причина не держаться за старый датасет.

## Как обновить

```bash
node scripts/rebuild-bike-paths.js
```

Скрипт запрашивает Overpass API (велодорожки в bbox Алматы по тегам
`highway=cycleway` / `cycleway=*` / `cycleway:{both,left,right}`),
**полностью перезаписывает** `src/data/almaty.json` и печатает сводку
(сколько сегментов, суммарная длина, сколько шума отсеяно).

Что делает по дороге:
- **Название по-русски** — берёт тег `name:ru`, а не сырой `name` (тот часто
  на казахском). У ~80% именованных way в Алматы `name:ru` есть.
- **Разночтения в name:ru** — разные контрибьюторы OSM иногда по-разному
  пишут name:ru одной и той же улицы (пример: «улица Каныша Сатпаева» vs
  «улица Сатпаева»). Такие случаи — в словарь `NAME_ALIASES` в начале файла,
  по мере находок. Если после прогона видишь на карте одну улицу под двумя
  разными именами в списке сегментов — это оно, добавляй алиас и гоняй заново.
- **Сшивка фрагментов** — OSM режет одну улицу на много `way`; жадный
  алгоритм по близости концов (≤60 м) склеивает их в непрерывные цепочки.
  Реальные разрывы велодорожки (>60 м) остаются отдельными сегментами — это
  нормально, не баг.
- **Безымянные way** — не выкидываются (иначе теряется реальное покрытие:
  ~75% велоинфраструктуры Алматы в OSM без тега `name`). Получают
  имя-заглушку `Велодорожка (OSM way <id>)`.
- **Шум** — исключены только явные MTB-трассы (в названии есть «XCO», сеть
  кросс-кантрийных велотрасс в предгорьях, не городская велодорожка).
  Список фильтров — `EXCLUDE_NAME_SUBSTR` в начале файла, дополнять при
  находках нового шума.

`safetyLevel` **не проставляется** — оценочное поле, в коде сейчас не
используется (`src/hooks/useMapData.ts` просто прокидывает его дальше, ни на
что не влияет), подтверждено владельцем как неважное. `source: "OSM"`,
`description` — generic «Загружено из OpenStreetMap (дата)».

## Важные грабли

- **Никогда не сериализуй `almaty.json` через `JSON.stringify(data, null, 2)`
  или `json.dump(..., indent=2)` напрямую.** Файл хранит координатные пары
  `[lon, lat]` в одну строку; generic-сериализация с отступом разворачивает
  каждое число на отдельную строку — весь файл переформатируется, диф на
  тысячи строк вместо реальных изменений (наступали в PR #176, пришлось
  переделывать руками). `scripts/rebuild-bike-paths.js` содержит свой
  `serialize()` — используй его или садись писать такой же.
- **Overpass иногда отвечает 406** без явного `User-Agent`/`Accept: */*` в
  заголовках — не полагайся на дефолты `fetch`. Возможны и 429/504 (публичный
  инстанс перегружен) — скрипт пробует зеркало `lz4.overpass-api.de`, но
  ретраить с паузой всё равно может понадобиться руками.
- **Не пуш в одну ветку по частям, если PR может смержиться раньше, чем ты
  допушишь всё.** В PR #177 часть коммитов ушла в уже смерженную ветку и
  осела мёртвым грузом — пришлось поднимать их в новом PR (#179). Если работа
  растянута на несколько заходов — либо предупреждай, что PR ещё не финален,
  либо не открывай PR, пока не готов весь набор изменений.
- После пересборки — полный набор проверок перед коммитом: `npm run lint`,
  `npm run format:check`, `npx tsc -b --noEmit`, `npm run build`,
  `npm run test:e2e` (для последнего может понадобиться
  `npx playwright install chromium`, если версия Playwright только что
  обновилась зависимостями — иначе тесты падают на «Executable doesn't
  exist», это не связано с самими велодорожками).

## Оформить как PR

Дальше — по стандартному флоу этого репозитория, см.
[[git-feature-workflow]] (`.claude/skills/git-feature-workflow/SKILL.md`):
ветка `feature/rebuild-bike-paths-<дата>` → коммит → push → `gh pr create`.

Commit message: `feat(map): пересобрать велодорожки Алматы из OSM`.

В теле PR — итоговые цифры из вывода скрипта (сегментов, км, сколько
безымянных, сколько шума отсеяно) и явно перечисли известные компромиссы:
ручных описаний Velojol больше нет, часть названий — заглушки с OSM id.
